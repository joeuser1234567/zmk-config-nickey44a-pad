# 左TPS43のUSBログ診断

## 目的と確認済み事項

左のキー入力は正常だが、左TPS43の長押し・2本指タップ・2本指上下操作は
すべて無反応。利用者の測定では電源3.3V、信号4本の導通あり、信号間6組の
短絡なし。同じTPS43は右側で動作した。これだけでは動作中のI2C通信や
RDY割り込みの正常性は確定しない。

まず既存のピン・ジェスチャ・省電力・左右間転送設定を維持し、左側のログを採る。
`build.yaml` の `nickey44a_l_debug` は通常の左側にUSBログと
INPUT/ZMKのDEBUGログを追加した診断用ビルド。

## ビルドと書き込み

1. この変更を自分のForkへcommit/pushして、GitHub ActionsのBuildが成功するまで待つ。
2. **その実行の** `firmware` artifactをダウンロードし、`nickey44a_l_debug.uf2` を取り出す。
   リポジトリ内の `firmware/v1.0.0` は今回の診断用ではない。
3. 左側だけをブートローダーモードにして診断用UF2を書き込む。
4. 右側は通常版のまま電源を入れ、PCとの接続と左右のキー入力を確認する。
   この診断では `settings_reset.uf2` は不要。

## Macでログを採る

左側をデータ通信可能なUSBケーブルでMacに接続し、ターミナルで実行する。

```sh
ls /dev/cu.usbmodem*
```

左側を接続したときに増えたポート名を使用する。次の `XXXX` は実際の名前に置き換える。

```sh
screen -L /dev/cu.usbmodemXXXX 115200
```

`screen -L` は現在のディレクトリに `screenlog.0` を保存する。
ログを開いた状態で、左パッドに触れず5秒、1本指の移動、長押し、2本指タップ、
2本指上下操作をそれぞれ数回行う。操作順とPC上の反応も記録する。
終了は `Ctrl-A`、続けて `K`、確認に `y`。

起動直後のログは接続前に流れて見えない場合がある。起動ログがないことだけで
初期化失敗とは判断しない。必要なら左側を通常リセット（ブートローダー用の
ダブルリセットではない）し、ポートを再確認してすぐに接続する。
それでも初期化ログを採れない場合は、採れたログを共有して起動ログ保持の対策へ進む。

## ログの読み方

固定されたAzoteqドライバー `66d510249d139569a4060c35bd78c6a2159f83ed`
の実際のログ文字列に基づく。

| ログ | 次に確認する場所 |
| --- | --- |
| `I2C bus not available` | I2Cコントローラーの初期化 |
| `Register ... read error` / `write error`、`Device not responding`、`Device configuration error` | I2C通信・電源・SDA/SCL・NRSTの動作。ログだけで故障部品は断定しない |
| `RDY interrupt configured` | RDY割り込みの登録成功。実際の信号変化の証明ではない |
| `TPS43 driver successfully initialized` | ドライバー初期化完了。ただしRDY登録失敗が警告だけで続行する場合があるので前の行も読む |
| `Touch state changed: down` / `up`、`Sending movement`、`Scrolling`、`Two finger tap` | 左側でタッチデータを取得できている。PCで反応しないなら左右間転送・右側処理を次に調べる |
| 初期化完了後、操作してもタッチログなし | RDY割り込み・センサー設定・省電力復帰を調べる |
| ログが全くない | まず診断UF2、USBケーブル、ポート、ログ接続を確認。TPS43故障とはまだ判断しない |

`NACK expected` と明記された通信終了ログは、それ単独では異常扱いしない。
左側の移動は既存設定で0倍にされるため、`Sending movement` が出てもカーソルが
動かないこと自体は想定どおり。長押し・2本指操作のログとPC反応を比較する。

共有するものは、取得できた起動部分から操作終了までの `screenlog.0`、
試した操作と順序、左右キー入力の可否。左ログだけでは右側への到達は証明できないため、
入力が確認できた段階で右側の受信ログの診断に進む。

診断後は通常の `nickey44a_l.uf2` に戻す。ログ有効時は動作タイミングや消費電力が変わる。
